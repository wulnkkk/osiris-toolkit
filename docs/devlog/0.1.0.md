# osiris-toolkit v0.1.0 Dev Log

## 2026-05-24 — Project Inception

**Decision**: Integrate three standalone OSIRIS tools (`osiris-deck-parser` v0.3.0, `osiris-data-lib` v0.1.0, `osiris-vis` v0.1.0) into a single package.

**Starting state:**
- Three independent packages with separate `pyproject.toml`, separate `.venv`, separate `src/` layouts
- `osiris-vis` already depended on `osiris-data-lib` via editable install
- No shared infrastructure between them
- Two modules had zero tests, one had hardcoded paths

**Design decisions:**
- Target: single installable package `osiris-toolkit`, CLI + Python API
- Architecture: `deck/` `io/` `sim/` `units/` `analysis/` `vis/` `workflow/` `sync/` `_generated/`
- Units driven by deck parser output, eliminating regex-based `omega_p0` extraction
- Declarative diagnostic type catalog (`DiagKind` dataclass) for auto-discovery
- English throughout (open-source project)
- MIT license target

**Architecture chosen:**

```
osiris-toolkit/
├── deck/         Input deck lexer, parser, validator
├── io/           ZDF binary format reader
├── sim/          Simulation directory discovery, 12 diagnostic types
├── units/        Normalized ↔ physical unit conversion
├── analysis/     Statistics, EMF energy/spectra, density profiles
├── vis/          Plotting: fields, density, phasespace, k-space, scattering
├── workflow/     YAML pipeline: deck → analyze → visualize
├── sync/         Fortran source extractor (dev-time)
└── _generated/   Auto-generated definitions
```

## 2026-05-25 — Task D-01, D-02: License Audit

**Investigation**: Traced the provenance of `io/zdf.py`. Discovered it is a direct derivative of ZPIC's `zdf.py` (Copyright 2017 Instituto Superior Tecnico, AGPL v3).

**Key findings:**
- `osiris-1.0.0/source/zdf/zdf.py` carries a full AGPL v3 header with IST copyright
- Our version had removed the original copyright notice — a compliance issue under AGPL v3 §4
- OSIRIS itself is AGPL v3, same license as ZPIC, same research group (IST/UCLA). No conflict there — OSIRIS never needed to change license.
- We need MIT, so AGPL code is incompatible — must be removed or rewritten.
- All other modules are original work (simulation.py, converter.py, deck parser, sync modules)
- Parameter schemas contain factual extractions (parameter names, types, defaults), not creative expression
- The ZDF format specification (`zdf/README.md`) has no license statement

**Decision**: Path 3 — clean-room rewrite of the ZDF reader from the format specification. This enables MIT licensing for the entire project.

**Three paths considered:**

| Path | Approach | Outcome |
|------|----------|---------|
| 1 | Claim non-derivative | Rejected — zdf.py is clearly a direct port |
| 2 | Keep AGPL, fix compliance | Viable but restricts downstream use |
| 3 | Clean-room rewrite from spec | Chosen — enables MIT, eliminates copyleft |

## 2026-05-25 — Task D-03, D-04: ZDF Clean-Room Rewrite

**Approach**: Implement a ZDF binary reader using ONLY:
1. The ZDF format specification (`zdf/README.md` — no license, functional description)
2. Empirical verification against real ZDF binary files

**Empirical analysis performed:**
- Read `zdftest.zdf` binary header → verified magic `ZDF1`, record type IDs
- Read large E-field file (6656×9888 cells, 517 chunk records) → verified chunked dataset protocol
- Verified record type ID values: `0x00030000=TYPE, 0x00210000=GRID, 0x00200000=ITERATION, 0x00100000=DATASET`

**Old architecture (deleted):**
- `io/zdf.py` — `ZDFfile` class, stateful file handle, 838 lines, derived from AGPL code

**New architecture:**

| File | Purpose | Lines |
|------|---------|-------|
| `io/_format.py` | Format constants: magic, record type IDs, dtype maps | ~100 |
| `io/_types.py` | Lightweight dataclasses: ZdfRecord, ZdfGridInfo, etc. | ~80 |
| `io/_reader.py` | Stateless pure functions: `read_grid()`, `read_particles()`, `read_tracks()` | ~530 |
| `io/_parallel.py` | Parallel batch I/O: `read_many()` with ThreadPoolExecutor | ~90 |
| `io/__init__.py` | Unified exports | ~50 |

**Key design decisions:**
- All functions are stateless (open→read→close). No shared state between calls.
- Inherently thread-safe — each call opens its own file handle
- Pickle-safe — module-level functions, no instance methods
- `_parallel.read_many()`: preserves input order, throttles via `max_workers`, cancel-on-error
- ZDF format constants derived from the spec + verified against real binary files
- Array reshaping: Fortran (column-major) order in file → C (row-major) numpy order
- `_read_file_type()` helper correctly handles the first (TYPE) record — reads record header, then parses the STRING data from the record body

**Compliance verification:**
- Zero code derived from `osiris-1.0.0/source/zdf/zdf.py`
- Zero code derived from `zdf.c` / `zdf.h`
- Record type IDs are functional constants (binary protocol), not creative expression
- ZDF format attribution preserved in `_format.py` and `__init__.py` docstrings
