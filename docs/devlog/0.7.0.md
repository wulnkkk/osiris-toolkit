# osiris-toolkit v0.7.0 Dev Log

> Core Update — Unified Field+Axis data model, AI-readiness infrastructure, particle-to-grid engine, and performance fix

## Core Feature: Unified Field+Axis Data Model (#40)

The `GridData` container has been upgraded to a full `Field` class with operator overloading and physical slicing. `GridData` is preserved as a backward-compatible alias.

### Field Operators

```python
from osiris_toolkit import Field

f1 = sim.get_field("e1", iteration=100)
f2 = sim.get_field("e2", iteration=100)

energy_density = (f1 ** 2 + f2 ** 2) * 0.5  # element-wise operations
difference = f1 - f2                         # Field - Field
scaled = f1 * 3.0                            # scalar multiplication
```

Supported operators: `+`, `-`, `*`, `/`, `**`, `-` (neg), `abs()` — all element-wise on `.data`, returning new `Field` objects with preserved metadata.

### Physical Slicing

```python
roi = field[50:150, 30:120]  # slice by grid indices
center = field[:, 64]         # scalar index along one axis
```

`__getitem__` returns a new `Field` with sliced data and updated axis metadata (min/max/npoints adjusted to the slice region).

### GridAxis Coordinate Methods

```python
ax = grid.axes[0]
idx = ax.value_to_index(5.0)     # physical → grid index
coord = ax.index_to_value(50)    # grid index → physical coordinate
```

`GridAxis` now carries `npoints` (set automatically during ZDF read) to enable these conversions.

## New Modules

### compute/deposit.py — Particle-to-Grid Engine (#37)

```python
from osiris_toolkit import particles_to_grid

grid = particles_to_grid(
    positions,            # (nparts, ndim) in grid-index space
    weights=None,         # or (nparts,) per-particle weights
    grid_shape=(64, 64),
    shape_function="tophat",  # ngp | tophat | triangular | spline3
)
```

Four shape functions: Nearest Grid Point (NGP), Cloud-In-Cell / tophat (CIC), quadratic spline (triangular), cubic spline (spline3). Numba acceleration is supported as an optional dependency via `use_numba=True`.

### _logging.py — Centralized Logging (#51)

```python
from osiris_toolkit._logging import get_logger, configure

logger = get_logger(__name__)
logger.info("Processing %d iterations", n)

# CLI control
osiris-toolkit --verbose vis batch ...    # DEBUG level
osiris-toolkit --quiet vis batch ...      # ERROR only
```

All library code now uses Python's `logging` module instead of `print()`. CLI layer keeps `click.echo()` for user-facing output.

## Simulation Enhancements

### info_field() — Metadata-Only Reads (#46)

```python
info = sim.info_field("e1", iteration=100)
# FieldInfo(quantity="e1", ndim=2, shape=(128, 256),
#           axes=[...], units="sim", report_type="")
```

`info_field()`, `info_raw()`, `info_tracks()` read ZDF metadata without loading data arrays. Types: `FieldInfo`, `ParticleInfo`, `TrackInfo`.

### Report Modifier Full-Chain Support (#25)

OSIRIS report modifiers (`savg`, `senv`, `line`, `slice`, `tavg`) are now detected during directory discovery and filterable in all accessors:

```python
# Get spatial average version of e1
field = sim.get_field("e1", iteration=100, report_type="savg")

# List only plain iterations (no modifier) — default behavior
sim.list_iterations("e1")  # report_type=None filters to plain only
```

Detection is filename-based (no ZDF file reads required), using known suffix patterns.

## Visualization

### 1D Line Plot Support (#26)

`plot_field()` now detects 1-D data and renders a line plot via `ax.plot()` instead of `ax.imshow()`:

```python
# 1D simulation output automatically renders as line plot
plot_field("e1", iteration=0, sim=sim)
```

### Overwrite Protection (#53)

All visualization functions now accept `overwrite=False` (default). When `False`, attempting to save to an existing file raises `FileExistsError`:

```python
plot_field("e1", 0, sim=sim, output="out.png")         # raises if exists
plot_field("e1", 0, sim=sim, output="out.png", overwrite=True)  # overwrites
```

CLI: `osiris-toolkit vis plot ... --overwrite`, `osiris-toolkit vis batch ... --overwrite`.

## Performance

### Parallel Batch Bottleneck Fix (#22)

Workers in `batch_process_parallel()` and analysis parallel functions no longer re-create `Simulation` objects. The `Simulation` (with its directory discovery cache) is created once in the parent process and pickled to workers via `ProcessPoolExecutor(spawn)`.

## Backward Compatibility

- `GridData = Field` — all existing code that constructs or type-checks `GridData` continues to work
- `GridAxis` — new `npoints` field defaults to 0; all existing constructors are compatible
- `plot_field()` — signature unchanged (new `overwrite` parameter has default `False`, but this is a behavior change: previously it would silently overwrite)
- `vis/parallel.py`, `analysis/parallel.py` — worker function signatures changed internally, but public API (`batch_process_parallel`, `field_energy_all`, `describe_all`) is unchanged
- All print output in library code has moved to `stderr` via `logging`; CLI output remains on `stdout` via `click.echo()`

## Breaking Changes

- **Overwrite default `False`**: Previously, re-running batch processing would silently overwrite existing output files. Now it raises `FileExistsError` unless `overwrite=True` is explicitly set.
- **Log output**: Library informational messages now go to `stderr` via the `logging` module instead of `stdout` via `print()`. Use `--verbose` to see them, `--quiet` to suppress.
