## Breaking Changes

None. v0.16.0 is a **documentation and tooling** release with no code API changes.

## Architectural Decisions

### 1. Agent Skills separated from human docs

**Problem**: Agent skills (`audience: agent`) were mixed into `docs/`, which is published
as a human-readable mkdocs website. This created semantic ambiguity and required a
non-standard mkdocs plugin to include content from external directories.

**Decision**: Move all agent-facing content into `skills/` at the project root, following
the [Agent Skills open standard](https://agentskills.io/) (`skill-name/SKILL.md` format).

**Rejected alternatives**:

| Alternative | Reason |
|-------------|--------|
| Keep in `.claude/skills/` | Platform-specific (Claude Code only); not cross-platform |
| Keep in `docs/` with include plugin | Added `mkdocs-include-markdown-plugin` dependency; path resolution issues |
| Symlink `docs/` to `.claude/` | Windows `git core.symlinks=false` prevents reliable symlinks |

**Result**: `docs/` is now pure human documentation. `skills/osiris-dev/` and
`skills/osiris-user/` are the canonical agent skill sources.

### 2. Cross-reference link strategy

**Problem**: Links from `skills/` to `docs/` must work in two contexts:
1. When an AI agent reads the skill file directly (on GitHub or locally)
2. When the skill content is referenced from mkdocs (via include)

**Decision**: Use two link styles depending on direction:

| Direction | Style | Why |
|-----------|-------|-----|
| `skills/` â†?`docs/` | GitHub absolute URL | `skills/` is outside mkdocs build tree; relative paths would break |
| `docs/` â†?`AGENTS.md` | Local relative path | Both at project root; works on GitHub |
| Within `skills/` | Local relative path | Agent Skills spec progressive disclosure |

### 3. Compliance check system

**Problem**: Architecture rules (no reverse deps, English-only, path leaks) were documented
but never automated. Both human developers and AI agents could unknowingly violate them.

**Decision**: Three new compliance scripts, enforced at three levels:

| Level | What catches it |
|-------|----------------|
| Pre-commit hooks (3 local hooks) | Architecture deps, English, doc sync â€?on every commit |
| CI `checks` job | Same checks â€?on every push/PR |
| Agent Submit Checklist | In `skills/osiris-dev/SKILL.md` â€?agent reads before coding |

**Scripts created**:

- `dev-tools/check_arch.py` â€?AST-based import scanner that verifies layer hierarchy.
  Prevents `compute/` from importing `sim/` or `vis/`. Also flags `UnitConverter` usage.
- `dev-tools/check_docs_sync.py` â€?Validates all `manifest.json` paths, all GitHub URL
  references from `skills/` to `docs/`, and ensures every `docs/` file has a mkdocs nav entry.
- `dev-tools/check_english.py` â€?Scans for CJK/Cyrillic/non-Latin characters in `.py`
  and `.md` files, excluding test data and `docs/note/`.

### 4. SemVer policy for 0.x

**Decision**: During `0.y.z` initial development phase, both `BREAKING CHANGE` and `feat`
increment MINOR (not MAJOR). This avoids premature graduation to 1.0.0 when API is still
unstable.

Configured via `[tool.commitizen.bump_map]` in `pyproject.toml`:

```toml
[tool.commitizen.bump_map]
BREAKING CHANGE = "MINOR"
feat = "MINOR"
fix = "PATCH"
```

When the project is ready for a stable 1.0.0, this section must be removed so that
`BREAKING CHANGE` reverts to incrementing MAJOR.

## New Features

### AGENTS.md cross-platform entry point

`AGENTS.md` at the project root serves as the single entry point for all AI tools.
Recognized by Claude Code, Cursor, GitHub Copilot, and Reasonix. Contains:
- Quick start commands
- Links to both agent skills
- Platform-specific configuration guides (Claude Code, Cursor, Copilot, Reasonix)
- Key rules summary
- Project structure overview

### Two agent skills in open standard format

- `skills/osiris-user/SKILL.md` â€?User skill: CLI commands, Python API, decision trees,
  known limitations (replaces `docs/agent-user/skill.md`)
- `skills/osiris-dev/SKILL.md` â€?Dev skill: architecture rules, dev workflow, code style,
  testing, release process, submit checklist (replaces `docs/agent-dev/dev-skill.md`)

Both skills include `Full Documentation Reference` sections linking to all relevant
`docs/` files (API reference, user guides, architecture docs, design docs).

### Skill contents also accessible via mkdocs

The old `docs/agent-dev/dev-skill.md` and `docs/agent-user/skill.md` were Include
wrappers that pulled content from the skill directories. These have been removed.
The mkdocs site no longer displays agent skill pages â€?skill content is agent-only.

## Migration Guide

If you have local branches based on v0.15.0, note:

- **Agent skill paths changed**: If you were referencing `docs/agent-dev/dev-skill.md`
  or `docs/agent-user/skill.md`, update to `skills/osiris-dev/SKILL.md` and
  `skills/osiris-user/SKILL.md`.
- **No code API changes**: v0.16.0 requires no changes to Python code or CLI usage.
- **New pre-commit hooks**: Run `uv run pre-commit install --hook-type pre-commit --hook-type commit-msg`
  to activate the three new compliance hooks.
