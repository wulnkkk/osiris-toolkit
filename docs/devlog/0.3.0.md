# osiris-toolkit v0.3.0 Dev Log

> Resource prediction module — estimate memory, runtime, and disk before cluster submission

## New Module: `resource/`

```
src/osiris_toolkit/resource/
├── __init__.py       # estimate_resources(deck) one-liner
├── _params.py        # ResourceParams: 25+ parameters from parsed deck
├── _estimator.py     # Memory, runtime, disk estimation formulas
└── _report.py        # Console report formatting
```

### CLI

```bash
osiris-toolkit deck estimate input.in
```

Outputs a formatted report with three sections: Simulation Summary, Memory (per-node breakdown), Runtime (CPU-hours + wall time), and Disk Space (per-diagnostic).

### Design

- **Memory formulas** derived from `init_buffer_spec`, `init_emf`, `init_current` in OSIRIS source
  - Particle arrays: exact bytes-per-particle per dimension (1D:44B, 2D:56B, 3D:68B)
  - Field VDFs: dynamic count (2-6) based on smoothing, external fields, part_grid_center
  - PML: per-boundary × auxiliary variable count
  - Current: per-thread VDF buffers
- **Runtime formulas** based on 23-step `iter_sim` main loop
  - Particle push (60 FLOP/p) + deposit (80 FLOP/p) + FDTD + smoothing + sort + collisions
  - PIC-typical 15% sustained efficiency
- **Disk formulas**: EMF (6 components × grid), raw particles (position+momentum+charge), restart (full snapshot)

### Benchmark: Au Simulation (slurm-37934638)

| Metric | Estimate | Real OSIRIS | Ratio |
|--------|----------|-------------|-------|
| Per-node memory | 388 MB | 969 MB | 0.40× |
| Grid | 4000×3600 | 4000×3600 | match |
| Steps | 88,850 | 88,850 | match |
| Processes | 360 | 360 | match |
| Species | 2 | 2 | match |

Memory under-estimate primarily due to `num_par_max` pre-allocation (electrons=20M, Au=11M per node) vs. average ppc-based estimate (~7.2M/node). Plus collision workspace, sorting buffers, and smoothing extra arrays not fully accounted.

## Known Limitations

- Particle memory uses average ppc, not `num_par_max` upper bound
- Collision workspace and auxiliary buffers not fully accounted
- Runtime is order-of-magnitude only (15% efficiency assumption)
