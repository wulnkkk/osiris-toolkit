### Cluster Utilities

| Function | Role |
|----------|------|
| `detect_available_workers()` | SLURM_CPUS_PER_TASK > OMP_NUM_THREADS > `os.cpu_count()` |
| `limit_blas_threads(n=1)` | Sets OMP/MKL/OPENBLAS/NUMEXPR_NUM_THREADS to prevent BLAS thread inflation |
| `detect_job_array()` | Reads SLURM_ARRAY_TASK_ID / PBS_ARRAYID environment variables |
| `detect_mpi_rank()` | Optional mpi4py detection; returns `None` if not installed |
| `split_iterations(its, rank, n)` | `iterations[rank::world_size]` even distribution |

All zero new dependencies. Uses stdlib `concurrent.futures.ProcessPoolExecutor` and `multiprocessing`.

## New Module: `analysis/parallel.py`

```
src/osiris_toolkit/analysis/parallel.py
```

Fan-out per-iteration analysis computations across processes:

| Function | Description |
|----------|-------------|
| `field_energy_all(sim, quantity, max_workers=None)` | Total field energy for all iterations in parallel |
| `describe_all(sim, quantity, iterations=None, max_workers=None)` | Statistical describe() for multiple iterations in parallel |

Each worker function is module-level (Windows spawn compatible), receives `sim_path: str`, constructs its own `Simulation`, computes, and returns a picklable `dict`.

## New Module: `vis/parallel.py`

```
src/osiris_toolkit/vis/parallel.py
```

Parallel batch visualization:

| Function | Description |
|----------|-------------|
| `batch_process_parallel(sim_path, sim_name, output_root, ...)` | Fan-out all (quantity, iteration) pairs across workers |

Three worker functions: `_worker_plot_field`, `_worker_plot_k_space`, `_worker_plot_density`. Scattering analysis (cross-iteration dependency) runs sequentially after all workers finish.

### Integration

`process_simulation()` in `vis/batch.py` gains a `max_workers` parameter. When `max_workers > 0`, it delegates to `batch_process_parallel()`. When `max_workers=None` (default), the existing sequential path is preserved.

### CLI

```bash
osiris-toolkit vis batch -o ./output -j auto /data/sim MySim    # auto-detect cores
osiris-toolkit vis batch -o ./output -j 8 /data/sim MySim       # explicit 8 workers
```

Added `--max-workers/-j` option to `vis batch` subcommand.

## Fix: `load_sim()` Anti-Pattern (all `vis/` modules)

Every plot function previously called `load_sim(sim_path)` which created a new `Simulation` object per call â€?600 redundant directory discoveries for a 100-iteration Ã— 6-field batch.

**Changes across all vis modules** (`field.py`, `density.py`, `kspace.py`, `phasespace.py`, `composite.py`, `scattering.py`):

- `load_sim()` in `common.py` accepts optional `sim=` keyword argument to reuse an existing `Simulation`
- All plot functions accept `sim=` and `converter=` keyword-only arguments
- `VisEngine` passes `sim=self._sim` instead of `sim_path=str(self._sim._path)`
- `process_simulation()` creates one `Simulation` and passes it to all plot calls

Fully backward compatible â€?old `sim_path` usage continues to work.

## Cross-Platform

| Concern | Resolution |
|---------|-----------|
| Windows spawn | All workers are module-level functions |
| BLAS thread inflation | `limit_blas_threads(1)` at top of every worker |
| matplotlib subprocess | Agg backend; each worker creates/destroys its own figure |
| pickle safety | All worker arguments are primitives (`str`, `int`, `float`) |
| MPI optional | `detect_mpi_rank()` returns `None` if mpi4py not installed |
| File write conflicts | Unique paths per `(quantity, iteration)` pair |

## Known Limitations

- Scattering analysis runs sequentially after parallel workers (cross-iteration dependency)
- Cross-iteration analysis aggregation (energy timeseries, etc.) not yet parallelized
- MPI mode (`mpi4py`-based multi-node) implemented but untested on real multi-node hardware
- k-space and scattering plots require 2D grids with axis metadata; synthetic test fixtures produce 1D-like data causing expected errors caught gracefully
