# osiris-toolkit v0.12.0 Dev Log

> HDF5 file format support — read OSIRIS HDF5 output transparently

## New Feature: HDF5 File Reader (#1)

OSIRIS can output simulation data in either ZDF or HDF5 format depending on
compile-time configuration. Previously, osiris-toolkit only supported ZDF files.
This release adds an HDF5 reader that makes the toolkit format-transparent.

```python
# Works the same for .zdf and .h5 files — just point at the output directory
sim = Simulation("/path/to/output")
field = sim.get_field("e1", iteration=50)  # auto-detects ZDF or HDF5
```

**How it works**:
- New `io/_reader_hdf5.py` module provides `read_grid()`, `read_particles()`,
  `read_tracks()`, `read_info()`, `list_records()` — same signatures as the
  ZDF reader
- `Simulation._discover()` now matches both `.zdf` and `.h5` file extensions
- Reader dispatch is automatic based on file extension, no user
  configuration needed
- `h5py` is an optional dependency: `pip install osiris-toolkit[hdf5]`

**HDF5-only metadata**: `ZdfFileInfo` now has a `simulation_info` field that
carries the `SIMULATION` attribute (git version, compile time, input file)
available in HDF5 files but absent from ZDF.

## Architecture

```
io/
├── _reader.py          # ZDF reader (existing)
├── _reader_hdf5.py     # HDF5 reader (new)
├── _types.py           # Shared dataclasses (ZdfFileInfo +simulation_info)
├── _format.py          # ZDF format constants
└── _parallel.py        # Parallel batch reads

sim/
└── simulation.py       # File discovery + reader dispatch by extension
```

All reader functions share the same return types (`ZdfFileInfo`, `ZdfGridInfo`,
`ZdfPartInfo`, `ZdfTrackInfo`, `ZdfIteration`), making the upper layers
(`analysis/`, `vis/`, `postproc.py`) completely format-agnostic.
