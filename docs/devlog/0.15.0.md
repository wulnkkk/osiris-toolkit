# osiris-toolkit v0.15.0 Dev Log

> UnitSystem architecture refactoring — QuantityKind, wavenumber support, k-space 2π fix

## Breaking Changes

### UnitConverter → UnitSystem

`UnitConverter` is deprecated in favor of `UnitSystem`. The new architecture splits monolithic unit conversion into composable pieces:

| Old | New |
|-----|-----|
| `UnitConverter(omega_p)` | `UnitSystem(omega_p, params)` |
| `converter.convert(data, "length", "um")` | `system.length.to(data, "um")` |
| `converter.get_label("time", "ps")` | `system.time.label("ps")` |
| `get_converter(sim)` | `get_system(sim)` |

All vis/analysis function signatures changed: `converter=` → `system=`.

### compute_k_space signature change

`omega0_norm` parameter removed. Unit normalization is now done through `UnitSystem.wavenumber`:

```python
# Old
kx_k0, ky_k0, spectrum = compute_k_space(data, dx, dy, omega0_norm=10.0)

# New
kx, ky, spectrum = compute_k_space(data, dx, dy)  # raw normalized angular wavenumber
qspec = QuantifiedSpectrum(kx, ky, spectrum, ..., system)
kx_k0 = qspec.kx.to("k0")  # k/k₀ via UnitSystem
```

### mask_energy signature change

Added `system: UnitSystem` parameter. `kx_range`/`ky_range` are now truly in k/k₀ units (previously off by 2π).

## New Features

### QuantityKind — immutable physical quantity descriptors (#78)

13 pre-defined quantity kinds: `LENGTH`, `TIME`, `E_FIELD`, `B_FIELD`, `WAVENUMBER` (new), `MOMENTUM`, `ENERGY`, `DENSITY`, `FREQUENCY`, `VELOCITY`, `CHARGE`, `CURRENT`, `MASS`.

Each carries unit scales, label templates, and LaTeX rendering support.

### UnitSystem — registry with resolved scales (#78)

Replaces `UnitConverter` with attribute-style access (`system.length`, `system.wavenumber`) and dict-style access (`system["e_field"]`). Scales are resolved at construction from `omega_p` and optional `SimulationParams`.

### Wavenumber quantity (#78, #77)

New `WAVENUMBER` quantity supports units: `norm` (k/k_p), `k0` (k/k₀, requires `omega0_norm`), `rad/um`, `rad/nm`, `um⁻¹`.

### QuantifiedGrid / QuantifiedSpectrum (#79)

Facade classes composing `GridData` / FFT results with `UnitSystem`:
- `qgrid.x.to("um")` — auto-infer quantity from unit
- `qgrid.as_quantity("e_field").to("GV/m")` — explicit quantity selection
- `qspec.kx.to("k0")` — wavenumber conversion without manual /(2π)

### K-space plot improvements (#70, #77)

- **Removed /(2π) double conversion** — k-space axes now correctly labeled in k/k₀
- **Adaptive xlim/ylim** — `_auto_k_range()` auto-determines plot range from signal extent (≥1% of peak)
- **k_unit parameter** — switch between `k0`, `rad/um`, `rad/nm`, `um⁻¹`, `norm` in `plot_k_space`

### CLI enhancements (#69, #68, #66)

- `vis plot --kind KSPACE`: new options `--k-unit`, `--omega0-norm`, `--xlim`, `--ylim`, `--clim`, `--white-low`, `--log-scale`
- `vis batch`: `--dry-run` for preview, `--progress` for tqdm bar
- `sim info --output json`: structured JSON output including `omega0_norm`

### SimulationParams extension (#4)

`SimulationParams` now extracts `omega0_norm` from deck sections (antenna/zpulse/laser).

## Fixes

- **K-space axis labels**: now match actual plotted coordinates (was off by 2π)
- **mask_energy**: `kx_range` now matches documented k/k₀ units (was off by 2π)
- **plot_spectrum** (energy.py): same 2π fix applied

## Architecture

```
UnitSystem(omega_p, params)          ← registry of QuantityKind instances
  └── QuantifiedGrid(grid, system)   ← GridData + unit conversion facade
  └── QuantifiedSpectrum(...)        ← FFT + wavenumber conversion facade
        └── vis / analysis layer     ← consumes Quantified* exclusively
```

All unit conversion now flows through a single entry point. No module outside `units/` performs bare mathematical unit conversion.
